## 1. Problem

### 1.1 문제 정의
| ID | 문제 | 내용 |
|---|---|---|
| P-1 | 수단 판단 | 같은 출퇴근길에도 지하철, 버스, PM 중 무엇이 나은지 날마다 다르지만 한눈에 비교할 수 없음 |
| P-2 | 반복 입력 | 매일 같은 길인데도 길찾기를 할 때마다 출발지, 도착지를 다시 입력해야 함 |
| P-3 | 개인차 | 길찾기 서비스의 평균 기준 소요 시간이 나의 걸음, 자전거 속도, 환승 속도와 맞지 않음 |
| P-4 | 출발 시각 | 늦지 않으려면 몇 시에 나가야 하는지를 사용자가 직접 거꾸로 계산해야 함 |
| P-5 | 현장 변수 | 대여소에 도착해서야 따릉이가 없거나 반납할 자리가 없음을 알게 됨 |
| P-6 | 첫, 마지막 구간 | 대중교통 길찾기는 집에서 첫 역까지, 마지막 역에서 목적지까지를 도보나 버스로만 안내해, 그 구간을 PM으로 줄이는 선택지를 비교할 수 없음 |

- 공통 제약: 출근 준비 중인 아침에는 여러 앱을 비교할 시간과 여유가 없어 결국 늘 하던 방식으로 이동

### 1.2 문제 상황 예시
| 상황 | 겪는 문제 |
|---|---|
| 지하철역까지 15분을 걸은 뒤에야 따릉이를 탔으면 5분이면 됐다는 것을 알게 됨 | P-6 |
| 따릉이로 역까지 가려고 대여소에 갔더니 자전거가 0대 | P-5 |
| 역 앞 대여소에 반납하려는데 거치대가 가득 차 다른 대여소를 찾느라 열차를 놓침 | P-5 |
| 대중교통 앱, 자전거 길찾기, 따릉이 앱을 번갈아 보며 머릿속으로 시간을 더함 | P-1, P-6 |
| 매일 같은 길찾기를 반복 입력하는 것이 번거로워 결국 확인하지 않고 출발 | P-2 |
| 길찾기 앱의 "도보 8분"이 실제로는 늘 11분이 걸림 | P-3 |

### 1.3 현재 대안과 한계
| 현재 대안 | 한계 |
|---|---|
| 대중교통 길찾기 앱 | 첫, 마지막 구간은 도보, 버스로만 안내. 매번 출발지, 도착지 입력 |
| 자전거 길찾기 | 대중교통과 섞은 경로를 만들지 않음 |
| 따릉이 앱 | 대여소 재고만 확인 가능. 대중교통과 비교 불가 |
| 공유 킥보드 앱 | 킥보드 위치는 보이지만 대중교통과 섞은 경로 비교 불가 |
| 습관대로 이동 | 확인 비용은 없지만 PM으로 줄일 수 있는 시간을 매일 놓침 |

### 1.4 근거
- 현재는 기획자 본인의 출퇴근 경험 기반
- 기획자 본인의 실사용 결과(따릉이 포함 경로가 표시된 날의 비율과 기본 경로 대비 시간 차이, 고른 경로의 정시 도착 여부)를 1차 근거로 활용 예정

## 2. Target

### 2.1 대상 정의
- 버스, 지하철로 출퇴근, 통학하며 첫 역까지, 마지막 역에서 목적지까지 걷거나 버스를 타는 사람
- 평일 대부분 같은 출발지와 도착지 사이를 반복 이동
- 첫, 마지막 구간이 짧지 않아 PM으로 바꿀 여지가 있음
- 지켜야 할 도착 시각(출근, 수업, 교대 인수인계 등)이 있음
- 휴대폰으로 교통 정보를 확인하는 데 익숙함

### 2.2 대상의 핵심 축
- 직업이나 나이가 아닌 "PM으로 줄일 수 있는 첫, 마지막 구간이 있는 반복 경로"가 공통 축
- 첫, 마지막 구간이 짧은 사람도 출발 시각 계산과 경로 비교의 이득은 있으나, PM의 이득이 가장 큰 사람은 첫 역까지 멀리 걷거나 버스를 갈아타는 사람

### 2.3 대상 세분
| 유형 | 특징 | 주된 니즈 | 대표 예시 사용자 |
|---|---|---|---|
| 환승형 직장인 | 버스, 지하철 환승이 섞인 경로. 집에서 역까지, 역에서 사무실까지 걷는 구간이 있음. 정시 출근 | 오늘 가장 빠른 조합과 출발 시각 | `persona.md` 예시 사용자 1 |
| 따릉이 병행 통학생 | 따릉이를 자주 이용. 날씨와 재고에 따라 수단을 바꿈. 요일마다 수업 시작 시각이 다름 | 재고를 반영한 따릉이 조합과 대중교통의 비교 | `persona.md` 예시 사용자 2 |
| 정시 도착 필수형 교대 근무자 | 근무 시작 시각이 근무조마다 다름. 걷는 시간을 줄이고 싶어 함 | 늦지 않는 출발 시각, 덜 걷는 경로 | `persona.md` 예시 사용자 3 |

### 2.4 사용 계기
| 계기 | 예시 | 서비스 내 역할 |
|---|---|---|
| 지각, 헛걸음 경험 | 역까지 걷다 늦음, 대여소에 자전거가 없어 헛걸음 | 첫 사용 계기 |
| 경로 변화 | 이사, 이직, 새 학기, 근무지 변경 | 첫 사용 또는 장소 재등록 계기 |
| 매일 출발 전 확인 | 출근, 등교 준비 중 오늘의 추천 확인 | 지속 사용 계기 (주 사용) |
| 퇴근, 하교 직전 확인 | 지금 가장 빠른 귀가 경로 확인 | 지속 사용 계기 |

### 2.5 대상이 아닌 사람
- 매일 이동 경로가 바뀌는 사람 (외근, 출장 위주): 장소 저장 구조의 이득이 적어 일반 길찾기가 더 적합
- 택시, 자가용으로 이동하는 사람

## 3. Solution

### 3.1 문제별 해결 방향
| 문제 | 해결 방향 |
|---|---|
| P-1 수단 판단 | 카카오맵 추천 경로(기본 경로)를 기준으로 따릉이 포함, 버스 전용, PM 전용 경로를 최대 4개까지 한 화면에 보여 주고, 기본 경로와의 시간 차이와 이유를 표시 |
| P-2 반복 입력 | 출발지, 도착지를 주소로 한 번 저장. 이후 앱을 열면 시간대에 맞는 출근 또는 퇴근 방향의 추천이 바로 표시 |
| P-3 개인차 | 첫 버전에서는 다루지 않음. 경로 추천이 안정된 뒤 출발, 도착 기록과 개인 보정을 고려 |
| P-4 출발 시각 | 목표 도착 시각에서 경로별 소요 시간과 여유 시간을 빼 "늦어도 출발해야 할 시각"을 계산 |
| P-5 현장 변수 | 따릉이는 대여 가능한 자전거가 있는 대여소와 반납할 자리가 있는 대여소만 골라 경로를 만들고, 재고를 확인하지 못하면 그 사실을 표시 |
| P-6 첫, 마지막 구간 | 기본 경로에는 첫, 마지막 도보 구간을 PM으로 바꾸면 줄어드는 시간을 표시. 첫 역까지 또는 마지막 역에서 멀거나 따릉이로 바꿔도 크게 느려지지 않으면 First, Last mile을 따릉이로 바꾼 경로를, 전 구간 따릉이가 30분 미만이면 전 구간 따릉이 경로를 표시. 출발지에서 도착지까지 자전거 경로도 함께 표시 |

### 3.2 해결의 흐름
| 순서 | 사용자 | 서비스 |
|---|---|---|
| 1. 등록 | 출발지, 도착지 주소를 한 번 입력하고 목표 도착 시각 설정 | 주소와 좌표를 기기에 보관 |
| 2. 확인 | 앱을 엶 | 기본 경로와 따릉이 포함, 버스 전용, PM 전용 경로를 만들어 이유, 출발 시각과 함께 표시 |
| 3. 선택 | 추천을 보고 탈 경로를 정함 | (상세 안내가 필요하면 카카오맵 길찾기로 연결, 권장 기능) |

- 2, 3이 매일 반복됨. 사용자가 하는 일은 앱을 열고 고르는 것뿐

### 3.3 해결 방식의 원칙
- 대중교통 경로는 카카오맵 대중교통 경로 API가 주는 것만 사용하고 직접 만들지 않음
- 따릉이 대체는 First mile(출발지 → 첫 지하철 승차역), Last mile(마지막 지하철 하차역 → 도착지)에만 적용. 중간 환승 구간은 바꾸지 않음
- 따릉이 구간의 시간은 대여소까지 걷는 시간, 자전거 이동 시간, 대여, 반납 시간을 모두 더해 계산
- 킥보드는 이용 가능 여부를 다루지 않고, 기본 경로의 도보 구간을 더 빠른 속도로 이동할 때 줄어드는 시간 계산에만 사용
- PM 전용 경로는 카카오 자전거 경로 그대로 사용
- 서버는 외부 서비스 호출을 중계하고 결과를 조합할 뿐, 사용자의 주소, 좌표를 보관하지 않음
