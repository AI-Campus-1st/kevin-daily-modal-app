## 0. 문서 정보
- 작성일: 2026-10-19
- 최종 수정: 2026-10-19 (추천 결과 4종 경로 반영)
- 근거 문서: `persona.md` (예시 사용자 3명), `functions.md` (기능 ID), `rules.md` (경로 생성, 표시 조건, 순서 규칙)
- 목적: 예시 사용자별 서비스 사용 패턴을 예상하고, 기능을 사용하는 과정에서 생기는 결과와 난관을 미리 확인
- 구성
  | 단계 | 다루는 내용 |
  |---|---|
  | 진입 | 서비스를 여는 시점과 여는 이유 |
  | 이용 | 사용자 행동, 사용 기능, 서비스 반응과 그 결과 |
  | 종료 | 서비스를 닫는 시점과 닫는 이유, 종료 시 상태 |
- 경로 구성, 거리, 시각, 소요 시간은 상황을 구체화하기 위한 예시이며 실제 값은 카카오 경로 API 응답에 따름
- `persona.md`의 "출퇴근 정보"는 예시 사용자가 지금까지 이용해 온 방식이며, 이 서비스가 보여 주는 경로는 4종 경로(기본, 따릉이 포함, 버스 전용, PM 전용)

## 2. 예시 사용자 1: 정다은 (환승형 직장인)

### S1-1 지각 다음 날 장소 등록
- 진입
  - 시점: 화요일 21:30, 집에서 휴식 중
  - 진입 이유: 전날 역까지 걷다 열차를 놓쳐 지각. 출근길을 비교해 볼 방법을 찾다 서비스를 알게 됨
- 이용
  | 순서 | 사용자 행동 | 사용 기능 | 서비스 반응, 발생 결과 |
  |---|---|---|---|
  | 1 | 출발지에 집 도로명 주소 일부 입력 | F-01 | 주소 후보 목록 표시 |
  | 2 | 후보 중 집 주소 선택, 이름 "집" | F-01 | 주소와 좌표를 기기에 저장 |
  | 3 | 도착지에 회사 건물 주소 입력, 선택, 이름 "회사" | F-01 | 출근(집 → 회사), 퇴근(회사 → 집) 방향 구성 |
  | 4 | 출근 목표 도착 시각 09:00 설정, 여유 시간 10분(기본값) 그대로 둠 | F-10 | 설정 저장 |
  | 5 | 등록 직후 보이는 추천 확인 | F-08 | 밤 시간대라 퇴근 방향 추천이 표시됨 |
- 종료
  - 시점: 21:35
  - 종료 이유: 등록이 끝났고, 출근 추천은 내일 아침에 확인하기로 함
  - 종료 시 상태: 장소 2개, 출근 목표 도착 시각 저장
- 확인 사항: 등록은 주소 두 번 입력과 목표 시각 설정으로 5분 안에 끝남. 등록 직후 밤 시간대에는 퇴근 방향이 보이므로, 등록 화면 끝에서 출근 방향 미리 보기를 제공할지 화면 설계에서 검토

### S1-2 평일 아침 출근
- 진입
  - 시점: 수요일 07:40, 화장을 마무리하는 중
  - 진입 이유: 어느 길로 나갈지 현관을 나서기 전에 정해야 함
- 이용
  | 순서 | 사용자 행동 | 사용 기능 | 서비스 반응, 발생 결과 |
  |---|---|---|---|
  | 1 | 홈 화면 아이콘으로 앱 열기 | F-02 | 아침이라 출근 방향. 입력 없음 |
  | 2 | (사용자 행동 없음) | F-03, F-04 | 기본 경로 "도보 7분(550m) → 망원역 6호선 → 합정역 2호선 → 강남역 → 도보 5분(400m)", 58분. 첫, 마지막 도보를 PM으로 바꾸면 "8분 단축" |
  | 3 | (사용자 행동 없음) | F-05 | 첫 역까지 도보 7분, 마지막 역에서 도보 5분이라 조건 1 불만족. First, Last mile 모두 따릉이로 바꾸면 오히려 느려져 대체 경로 없음. 전 구간 따릉이는 30분 이상. 따릉이 포함 경로 표시 안 함 |
  | 4 | (사용자 행동 없음) | F-06, F-07 | 버스 전용 경로 64분, PM 전용 경로(자전거 길 14.2km) 56분 |
  | 5 | 추천 카드 확인 | F-08, F-09 | 1순위 기본 경로 58분, 2번째 PM 전용 "기본 경로보다 2분 빠름", 3번째 버스 전용 "기본 경로보다 6분 느림" |
  | 6 | 출발 시각 확인 | F-10 | 기본 경로 "늦어도 07:52 출발" (여유 10분 포함) |
  | 7 | 기본 경로를 따르기로 하고 앱을 닫음 | - | - |
- 종료
  - 시점: 07:41
  - 종료 이유: 탈 경로와 출발 시각을 정함
  - 종료 시 상태: 저장 정보 변화 없음
- 확인 사항
  - PM 전용 경로는 대여, 반납, 재고를 반영하지 않은 자전거 이동 시간이라, 기본 경로보다 빠르게 보여도 실제로 그 시간에 도착하기 어려울 수 있음. 카드에 "자전거 길 기준"임을 분명히 표시해야 함
  - 기본 경로의 "PM으로 바꾸면 8분 단축"은 킥보드를 쓰는 사용자에게만 의미가 있으므로, 문구에 기준(킥보드 속도)을 짧게 밝힐지 화면 설계에서 검토

## 3. 예시 사용자 2: 김도윤 (따릉이 병행 통학생)

### S2-1 집 근처 대여소에 자전거가 없는 날
- 진입
  - 시점: 월요일 08:20, 옷을 입는 중
  - 진입 이유: 1교시 09:00. 따릉이로 갈 수 있는지 확인
- 이용
  | 순서 | 사용자 행동 | 사용 기능 | 서비스 반응, 발생 결과 |
  |---|---|---|---|
  | 1 | 앱 열기 | F-02, F-03 | 등교 방향. 기본 경로 "도보 8분 → 건대입구역 2호선 → 한양대역 → 도보 7분", 25분 |
  | 2 | (사용자 행동 없음) | F-05 | 첫 역까지 도보 8분, 마지막 역에서 도보 7분이라 조건 1 불만족, First, Last mile 대체로는 빨라지지 않음. 전 구간 따릉이 19분으로 조건 3 만족. 집에서 가장 가까운 대여소 자전거 0대, 반경 500m 안 두 번째 대여소 2대를 대여 대여소로 선택 |
  | 3 | (사용자 행동 없음) | F-06, F-07 | 버스 전용 26분, PM 전용(자전거 길 3.4km) 13분 |
  | 4 | 추천 카드 확인 | F-08, F-09 | 1순위 기본 경로 25분, 이어서 PM 전용 13분, 따릉이 포함(전 구간) 19분 "따릉이로만 19분, 대여소 자전거 2대", 버스 전용 26분 |
  | 5 | 따릉이 포함 경로의 대여소 이름과 대여소까지 도보 4분을 확인하고 출발 | - | - |
- 종료
  - 시점: 08:22
  - 종료 이유: 자전거가 있는 대여소를 확인하고 출발
  - 종료 시 상태: 변화 없음
- 확인 사항
  - 예시 사용자가 이용해 온 "따릉이 직행"이 조건 3의 전 구간 따릉이 경로로 나타남
  - 가장 가까운 대여소가 비어 있어도 반경 안 다른 대여소로 경로가 만들어져 헛걸음을 막음
  - 대여소 이름만으로 위치를 모르는 경우가 있어 대여소까지의 도보 시간을 함께 표시해야 함. 지도 표시는 권장 F-16
  - 요일마다 수업 시작 시각이 달라 목표 도착 시각을 매번 바꿔야 함. 권장 F-21로 해결

- 진입
  - 시점: 화요일 05:55, 준비를 마치기 직전
  - 진입 이유: 인수인계 20분 전(06:40)까지 도착해야 하며, 걷는 시간을 줄이고 싶음

  | 2 | (사용자 행동 없음) | F-05 | 지하철이 없어 첫, 마지막 버스 정류장을 기준으로 판단. 첫 정류장까지 도보 4분, 마지막 정류장에서 도보 2분이라 조건 1 불만족, 대체해도 빨라지지 않음. 전 구간 따릉이 18분으로 조건 3 만족 |

  | 4 | 추천 카드 확인 | F-08 | 기본 경로 25분, PM 전용 14분, 따릉이 포함(전 구간) 18분 "대여소 자전거 4대" |
  | 5 | 출발 시각 확인 | F-10 | 목표 06:40, 여유 10분 기준 기본 경로 "늦어도 06:05 출발", 따릉이 포함 "늦어도 06:12 출발" |

  - 종료 이유: 따릉이로 가면 여유가 있음을 확인

  - 실시간 도착 정보가 없어 이른 아침 버스의 긴 배차 간격이 기본 경로 소요 시간에 얼마나 반영되는지 알 수 없음 (`datasource.md` C-4)
  - 근무조마다 목표 도착 시각이 달라 매번 설정을 바꿔야 함. 권장 F-21로 해결

## 5. 시나리오에서 확인된 사항

### 5.1 단계별 진입, 종료 이유 정리
| 단계 | 반복되는 이유 | 해당 시나리오 |
|---|---|---|
| 진입 | 집을 나서기 직전, 어느 길로 나갈지 결정 | S1-2, S2-1, S2-2, S3-1 |
| 진입 | 퇴근 직전 지금 나은 경로 확인 | S3-2 |
| 진입 | 지각 경험 직후 첫 등록 | S1-1 |
| 진입 | 기기 변경 등 관리 목적 | S3-3 |
| 종료 | 탈 경로와 출발 시각을 정함 | S1-2, S2-1, S2-2, S3-1, S3-2 |

- 한 번의 이동에 앱을 한 번 엶. 여는 순간 추천이 보여야 하며, 화면을 보는 시간은 1 ~ 2분

### 5.2 반영할 사항
