## 2. 지도
| 요소 | 표시 |
|---|---|
| 버스, 지하철 구간 | 노선의 수단 색 실선 (`DESIGN.md` 2.4.2, 2.4.3) |
| 따릉이 구간 | `mode-bike` 실선 |
| PM 전용 경로 | `mode-pm` 실선 |
| 도보 구간 | `mode-walk` 점선 |
| 출발지, 도착지 | `badge-neutral` "출발", "도착" |
| 따릉이 대여소 | `badge-rank` "대여", "반납" |
| 환승 지점 | `transfer-point` 원 (`DESIGN.md` 7.7) |

- 처음 열 때 경로 전체가 보이도록 지도 범위를 자동으로 맞춤. 이후 확대, 이동은 사용자가 함
- 지도 영역은 콘텐츠 열 너비에 맞춘 정사각형
- 선 굵기 5(카카오 지도 단위 px)
- 환승 지점: 구간 사이에서 수단이 바뀌는 곳마다 원 하나. 따릉이 구간 안의 대여소(도보 → 따릉이), 반납 대여소(따릉이 → 도보)도 포함. 출발지, 도착지에는 두지 않음
  - 원의 중심이 그 지점. 테두리 색은 환승 뒤 수단 색
  - 위치는 환승 뒤 구간의 첫 좌표. 그 구간에 좌표가 없으면 앞 구간의 마지막 좌표, 둘 다 없으면 두지 않음
  - 겹치는 순서: 경로 선 < 환승 지점 < 출발, 도착, 대여소 표시
- 따릉이 구간의 선 = 대여소까지 도보(점선) + 대여소 사이 자전거(실선) + 반납 대여소에서 도보(점선)
- 좌표가 없는 구간(도보, 자전거 경로 응답에 좌표가 없을 때)은 선을 그리지 않음
- 기본 경로, 버스 전용 경로의 출발 도보, 도착 도보 조회에 실패하면(`edgeWalkKnown` 거짓) 그 도보 선은 그리지 않음

## 3. 데이터
- 새로 조회하지 않고, SC-01이 마지막으로 받은 응답(화면 메모리)에서 주소의 경로 종류를 꺼내 씀
- 출발지, 도착지 좌표는 SC-01이 그 응답을 요청할 때 보낸 좌표
- 화면 주소에는 경로 종류만 넣고 좌표는 넣지 않음 (`screens.md` 3.6)

## 4. 상태
| 상태 | 조건 | 표시 |
|---|---|---|
| 정상 | 지도 SDK를 불러옴 | 1장 구성 |
| 지도 불러오기 실패 | 지도 SDK를 불러오지 못함, 지도 키가 없음 | 지도 자리에 `map-frame` 대신 `empty-state` 모양으로 "지도를 불러오지 못했습니다". 범례는 그대로 표시 |
| 경로 없음 | 받은 응답이 없음(새 창에서 바로 열기 등), 응답에 그 경로 종류가 없음 | `#today`로 바꿈 |
