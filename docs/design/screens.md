## 2. 화면 흐름
```
            설정 버튼, 장소 등록                 장소 행
  SC-01  ----------------------->  SC-02  ----------------------->  SC-03
오늘의 추천 <-----------------------   설정   <-----------------------  장소 입력
                 뒤로 가기                        저장, 삭제, 뒤로 가기
   |  ^
   |  |  뒤로 가기
   v  |
  SC-04
 경로 지도   (펼친 카드의 "지도 보기")
```

| 출발 | 행동 | 도착 |
|---|---|---|
| 앱 열기 | 장소 2개가 모두 저장되어 있음 | SC-01 (추천) |
| 앱 열기 | 저장된 장소가 2개 미만 | SC-01 (장소 미등록 상태) |
| SC-01 장소 미등록 상태 | "장소 등록" | SC-02 |
| SC-01 | 설정 버튼 | SC-02 |
| SC-02 | 출발지 또는 도착지 행 | SC-03 (해당 칸) |
| SC-03 | "저장", 장소 삭제 확인, 뒤로 가기 | SC-02 |
| SC-02 | 뒤로 가기 | SC-01. 저장하지 않은 설정이 있으면 확인 창 먼저 (`screen-settings.md` 5장) |
| SC-02 | 저장 정보 모두 지우기 확인 | SC-01 (장소 미등록 상태) |
| SC-01 | 펼친 카드의 "지도 보기" | SC-04 (그 카드의 경로) |
| SC-04 | 뒤로 가기 | SC-01 |
| SC-04 | 받은 응답이 없거나 그 경로가 없음 | SC-01 (`screen-map.md` 4장) |

- 처음 등록: SC-01 장소 미등록 상태의 "장소 등록"으로 SC-02에 들어가 장소 2개와 목표 도착 시각을 입력. 별도 안내 단계 없음 (2026-10-20 사용자 결정)
- 등록 직후의 방향은 지금 시각 기준 (`rules.md` 9장). 반대 방향은 SC-01 머리 영역의 출근 퇴근 전환으로 확인하며 별도 미리 보기 기능 없음 (`scenario.md` R-3, 2026-10-20 사용자 결정)

## 3. 공통 규칙

### 3.1 화면 이동
- 주소의 `#` 뒤 이름으로 화면을 바꿈 (`tech_stack.md` 4.4)
- 목록에 없는 주소, 빈 주소는 `#today`로 바꿈
- 기기의 뒤로 가기와 `top-bar`의 뒤로 가기 버튼은 같은 동작
- SC-03에서 저장하지 않고 나가면 입력 내용을 버림. 확인 창 없음

### 3.2 화면 틀
- 바탕은 `canvas`, 휴대폰 세로 기준 단일 열, 좌우 여백 `spacing.md`
- 화면 너비가 `layout.mobile-max`를 넘으면 콘텐츠 열을 그 너비로 고정하고 가운데 정렬 (`DESIGN.md` 4.2)
- 머리 영역: SC-01은 `header-gradient`, SC-02 ~ SC-04는 `top-bar`(뒤로 가기 버튼, 화면 제목)
- 화면 안 구역과 구역 사이는 `spacing.xxl`, 카드와 카드 사이는 `spacing.sm` (`DESIGN.md` 4.1)
- 화면의 주요 행동 버튼은 화면 아래쪽 (`DESIGN.md` 4.2)

### 3.3 값 표시 형식
| 값 | 형식 | 분 단위 처리 | 근거 |
|---|---|---|---|
| 시각 | 24시간제 `HH:MM` (예: "07:52") | 출발 시각은 버림, 도착 시각은 올림 | `rules.md` 2장, `DESIGN.md` 10장 |
| 소요 시간 | "N분" (60분 이상도 분으로만, 예: "72분") | 올림 | `rules.md` 2장, `DESIGN.md` 10장 |
| 줄어드는 시간 | "N분" | 버림 | `rules.md` 2장 |
| 거리 | "N.Nkm" (소수 첫째 자리) | - | `rules.md` 11.1 |

- 시각, 분 숫자는 고정폭 숫자로 표시 (`DESIGN.md` 3.1)

### 3.4 접근성
- 누를 수 있는 요소는 가로, 세로 `layout.touch-target` 이상, 버튼끼리 `spacing.xs` 이상 간격 (`DESIGN.md` 4.3)
- 아이콘만 있는 버튼에는 화면 낭독기용 이름을 붙임 (각 화면 명세의 "이름")
- 상태는 색만으로 구분하지 않고 배지 문구를 함께 둠 (`DESIGN.md` 8장)
- 키보드 초점은 `layout.focus-ring` (`DESIGN.md` 7장)
- 선택 목록에서 고른 행에는 확인 아이콘과 화면 낭독기용 "선택되었습니다"을 함께 둠

### 3.5 공통 알림
- 짧은 알림은 `toast`. 화면 아래쪽에 나타나고 몇 초 뒤 사라짐 (`DESIGN.md` 7.6)
- 되돌릴 수 없는 작업은 첫 버튼을 `button-ghost`로 두고, 확인 `modal` 안의 마지막 버튼만 `button-caution` (`DESIGN.md` 7.3)

### 3.6 개인정보
- 주소 검색어와 좌표는 주소(URL)에 넣지 않음. 화면 주소에는 화면 이름, 장소 칸(`origin`, `destination`), 경로 종류(`base`, `bikeMix`, `busOnly`, `pmOnly`)만 들어감 (`api_spec.md` 1.1, `frontend/CLAUDE.md` 5장)
