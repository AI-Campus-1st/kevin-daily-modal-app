## 1. 프로젝트 개요
- 서비스 정체성 (`product.md` 1.1)
  > 저장해 둔 출퇴근길의 카카오맵 추천 경로를 기준으로, 첫, 마지막 구간을 따릉이로 바꾼 경로와 버스만, PM만 타는 경로까지 함께 보여 주고 앱을 여는 순간 출발 시각을 알려 주는 서비스
- 추천 결과: 기본 경로(1순위), 따릉이 포함 경로, 버스 전용 경로, PM 전용 경로 최대 4개 (`functions.md` 0.1)
- 첫 버전 범위: `functions.md`의 필수 기능 F-01 ~ F-12
- 권장 기능은 필수 기능 완료 후 본인 사용 중 필요가 확인되는 순서대로 추가 (6단계)
  - 출발, 도착 기록(F-13)과 개인 보정(F-14)은 경로 추천 시스템의 안정화, 고도화 이후 고려
- 불요 기능 N-02 ~ N-05는 이 계획에 포함하지 않음

## 2. 작업 규칙 체계

### 2.1 CLAUDE.md 계층
| 파일 | 적용 범위 | 상태 |
|---|---|---|
| `CLAUDE.md` (root) | 프로젝트 전역 작업 규칙. 모든 폴더, 모든 작업에 적용 | 작성 완료 |
| `backend/CLAUDE.md` | `backend/` 폴더 안의 작업에만 적용되는 하위 규칙 | 작성 완료 (2026-10-19) |
| `frontend/CLAUDE.md` | `frontend/` 폴더 안의 작업에만 적용되는 하위 규칙. 기기 저장 형식 포함 | 작성 완료 (2026-10-19) |

- 하위 규칙은 root 규칙과 함께 적용하며, 충돌하면 root 규칙이 우선
- 새 하위 폴더에 규칙이 필요해지면 같은 방식으로 해당 폴더에 `CLAUDE.md`를 추가하고 이 표에 기록

### 2.2 root 규칙의 적용
| 규칙 (`CLAUDE.md`) | 적용 방법 |
|---|---|
| 1. git 작업은 허락 후에만 | 커밋, push 모두 매번 사용자 확인 |
| 2. 문장 끝맺음 | 마크다운, Python docstring, JS 주석 모두 '~음' 또는 명사로 끝냄 |
| 3. 이모지 금지 | 코드, 주석, 문서 전체 |
| 4. 제외한 범위는 다시 꺼내지 않음 | `product.md` 6.2 범위 밖, `functions.md` 6장 불요 기능을 이후 문서에서 다시 제기하지 않음 |
| 5. 응답 및 코드, 문서 작성 지침 | Python 작은따옴표, 기능 구현 시 사용한 코드 개념 설명, 코드 파일은 요청 시에만 제시, 모호한 부분은 사용자에게 질문 |
| 6. 디자인 가이드라인 준수 | 화면 명세와 프론트엔드 모두 `DESIGN.md` 토큰, 컴포넌트만 사용 |
